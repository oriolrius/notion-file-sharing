NFS 2.0.0 is a full rewrite in Rust. It replaces the OpenResty/Lua server and the Lua CLI with one static binary and a 10 MB container image. **Every existing link keeps working.**

## Highlights

- **Web generator** at `/_/`: paste the Notion "copy link to block" URL, choose the expiry, an optional short alias and an optional password, and get the secure URL and the short URL. Login with OIDC (Keycloak). Ubuntu font, light and dark mode, works without JavaScript.
- **Password-protected links** (new v2 format): argon2id hash inside the encrypted token; the viewer enters the password once (12 h cookie scoped to the link).
- **Seek and resume**: HTTP `Range`/`If-Range` pass through to the file host (`206 Partial Content`). Video players can jump, and downloads can resume.
- **Notion cache**: one Notion API call per file per hour instead of one per request (Notion allows ~3 requests/s).
- **Short URLs expire with the link.** The old CLI always created Kutt links that expired after 7 days, even for 50-year links. Links of 10 years or more now get a short URL without expiry.

## Compatibility

- v1 links (`/<sig>/<customer>/<expire>/<cipher>`) are byte compatible: same libsodium secretbox layout, same SHA-1 signature. The test suite decodes vectors generated by the original Lua code, and production links were verified against the old server (identical bytes).
- New links without a password are still v1, so other tools that create or read v1 links keep working.
- Same responses as before: `application/octet-stream` + `Content-Disposition: attachment`.

## Operations

- `:8080` links and generator, `:9100` `/metrics` (Prometheus) and `/healthz` (internal).
- TLS always verified (the Lua server disabled verification towards Notion and S3).
- Non-root distroless image, read-only friendly, built only by GitHub Actions with build provenance attestation.
- CLI without Docker: `nfs create`, `nfs decode`, `nfs keygen` (static x86_64 musl binary attached to this release).

## Breaking changes

- Configuration moves from `modules/config.lua` to a TOML file (`config.example.toml`). Secrets can be read from files.
- The `nfs.sh` / `nfs_decode.sh` Docker wrappers are gone: use the `nfs` binary.
- `-K/--key-file`, `-G/--generate-key`, `-D/--debug` and `-L/--debug-file` were removed: the key comes from the config, `nfs keygen` creates keys, and `RUST_LOG` sets the log level.
