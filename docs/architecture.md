# Architecture

## Components (`src/`)

| Module | Role |
|---|---|
| `main.rs` | CLI: `serve`, `create`, `decode`, `keygen`, `health` |
| `config.rs` | TOML config; secrets inline or `*_file` |
| `token.rs` | Link codecs v1 (frozen) and v2, key derivation, argon2id password hash |
| `links.rs` | Notion URL → block id, expiry parsing, link building (shared by CLI and web) |
| `notion.rs` | Notion API client + cache of file URLs |
| `kutt.rs` | Kutt short links (create, delete, unshorten) |
| `server/download.rs` | Public link handling, password unlock, streaming with `Range` |
| `server/web.rs` | Generator `/_/` and embedded assets |
| `server/auth.rs` | OIDC login (authorization code + PKCE, confidential client) |
| `server/metrics.rs` | Prometheus counters on the admin listener |
| `templates/`, `assets/` | askama templates, CSS/JS, Ubuntu fonts (all embedded in the binary) |

Stack: tokio, axum 0.8, reqwest 0.13 (rustls + ring, system CA roots), moka, askama, RustCrypto.

## Link formats

### v1 — frozen, byte compatible with the Lua server

```
/<sig>/<customer_id>/<expire_ts>/<cipher_b64>
cipher_b64 = base64(nonce[24] ‖ crypto_secretbox_easy(block_id, nonce, key))   # XSalsa20-Poly1305
sig        = hex(sha1(customer_id ‖ expire_ts ‖ cipher_b64 ‖ base64(key) ‖ seed))
```

- The signature covers the raw strings of the URL. The cipher may contain `/`, `+`, `=`.
- `src/token.rs` tests decode vectors generated by the original Lua code.
- Other tools generate v1 links with the same key and seed, so the format must never change.

### v2 — password links

```
/v2/<base64url(nonce[24] ‖ secretbox(json, k2))>      k2 = HMAC-SHA256(key, "nfs/v2/token")
json = {"b": block_id, "c": customer_id, "e": expire_ts, "p": {"s": salt, "h": argon2id}}
```

The secretbox MAC authenticates the payload; no separate signature. A correct password sets an
encrypted cookie (scoped to the link path) valid for 12 h or until the link expires.

## Request flow

1. Parse and verify the link (constant-time comparison). Expired → `410`, anything else → `404`.
2. Resolve the block with the Notion API. The file URL is valid for one hour; it is cached until
   5 minutes before `expiry_time`, and concurrent misses share one API call (Notion allows
   ~3 requests/s, and a video player sends many `Range` requests).
3. `GET` the file with the client's `Range`/`If-Range`, then stream the body. Status 200/206/416 and
   `Content-Length`, `Content-Range`, `ETag`, `Last-Modified` pass through. A `403` from the file host
   (URL expired early) triggers one fresh resolution.
4. External files (`external` blocks) are redirected, never proxied.

Responses keep the original behaviour: `application/octet-stream` + `Content-Disposition: attachment`.

## Generator and login

- `/_/` needs a session; without one it redirects to `/_/auth/login` (OIDC).
- The ID token comes straight from the token endpoint over TLS (OIDC Core 3.1.3.7), so its
  signature is not checked; `iss`, `aud`, `nonce` and `exp` are.
- Session: encrypted cookie (key derived from the main key), 12 h, CSRF token for `POST /_/links`.
- Before creating a link the server resolves the block (it must exist and be shared with the
  integration) and reads the file size with a 1-byte range request.
- New links are v1 without password and v2 with password. The short URL expires with the link
  (no expiry for links of 10 years or more).

## Security notes

- Secrets: the 32-byte key and the seed sign and decrypt every link. Keep them in a vault; never
  rotate them while links are in use.
- TLS is always verified (system CA store in the image).
- HTML pages: strict CSP (`'self'` only), `no-referrer`, `nosniff`, `frame-ancestors 'none'`.
- Password attempts: 10 per IP per 10 minutes (`X-Real-IP` from the reverse proxy).
- Logs never contain file URLs, tokens or keys (only the first 8 characters of a link id).
